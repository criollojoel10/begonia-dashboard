# begonia en Phosh: estado final (2026-11-20)

Sustituye a Plasma Mobile (retirado) en el Redmi Note 8 Pro (`begonia`, MT6785).
Todo lo de abajo está medido en el dispositivo tras el último flasheo.

## Stack

| pieza | valor |
|---|---|
| kernel | `7.1.0` Kupfer (vendor MT6785), boot verificado `17b347242e63…` |
| rootfs | Arch Linux ARM, ext4 10 GiB, label `kupfer_root` |
| escritorio | **Phosh 0.59.0** + `phoc` 0.59.0 (wlroots/KMS) |
| teclado | **squeekboard 1.43.1** |
| terminal | `kgx` (GNOME Console) |
| navegador | **epiphany 51.3** (GNOME Web/WebKit, UI móvil adaptativa) |
| red | NetworkManager (solo `wlan0` gestionada) |

## Por qué Phosh y no GNOME Mobile

- **Phosh** está empaquetado en Arch Linux ARM (`phosh`, `phoc`) y ya estaba verificado
  en este mismo equipo (`begonia-linux/docs/UI-PHOSH.md`).
- **GNOME Mobile** existe, pero solo como `gnome-shell-mobile` + `mutter-mobile` +
  `gnome-settings-daemon-mobile` en **AUR** (compilación de fuente para aarch64, fork
  `gitlab.gnome.org/verdre/gnome-shell-mobile`, GNOME 48). En postmarketOS está marcado
  como *Experimental*. No hay paquete para ALARM/Kupfer: instalarlo exige compilar
  GNOME Shell y Mutter en el teléfono (horas, y reemplaza `gnome-shell`).

Diferencia práctica: Phosh es un shell móvil ligero sobre phoc (wlroots) + GTK, pensado
para telefonos; GNOME Mobile es GNOME Shell completo parcheado (Mutter), más pesado y
con más apps adaptativas, pero inmaduro y sin paquete en ALARM.

## Táctil (Tianma)

El panel es **Tianma**, pero el DTB de begonia pide el nombre CSOT. El blob correcto
debe ir **con el nombre CSOT**:

```
/lib/firmware/novatek/nt36672a_begonia_csot.bin.zst  <- contenido Tianma
md5 7d67c2e9167f1a630576c177c1b831f7
```

Resultado: `input: spi1.0 ... /dev/input/event3`; ejes correctos (antes iban
invertidos con el blob CSOT real). El firmware se instala desde
`mt6785-mainline/firmware` (`novatek/`, `mediatek/`).

## Pantalla / arranque

`card1-DSI-1` 1080×2340@60, panfrost en `13040000.gpu`. El panel DSI a veces tarda o
falla el probe (`sending dcs data ff 25 failed: -62`); si phoc arranca antes de que
exista `/dev/dri/card1` muere con `Found 0 GPUs`. Mitigación instalada:

- `.bash_profile` espera hasta 90 s a `/dev/dri/card1` antes de `exec phosh-session`.
- `getty@tty1` con `StartLimitIntervalSec=0` (reintenta siempre).
- `sshd` con `Restart=always` y `StartLimitIntervalSec=0`.

## WiFi

- Solo `wlan0` la gestiona NetworkManager.
  `wlan1`, `ap0`, `p2p0`, `p2p1` van como `unmanaged` (`/etc/NetworkManager/conf.d/`).
  `p2p-dev-wlan0` sigue existiendo (dispositivo virtual de NM), pero no se ofrece como
  red conectable.
- Perfiles guardados: `SKYLIFE_ALEJANDRA_5G` y `CLARO_JOEL` (autoconnect).
- Apagar/encender y reconectar, probado:

```
nmcli radio wifi off   -> radio disabled, wlan0 DOWN
nmcli radio wifi on    -> enabled; autoconnect a SKYLIFE_ALEJANDRA_5G
                          wlan0 UP 192.168.1.174/24
```

Cualquier otra red se añade desde Ajustes → Wi-Fi (Phosh) o `nmcli device wifi connect`.

## Rendimiento

`begonia-performance.service` (enabled) fija al arrancar:

| dominio | valor |
|---|---|
| CPU | governor `performance`, 2 000 000 kHz (máx) |
| GPU (Mali-G76) | devfreq `userspace`, `min_freq = max_freq = 900 000 000` |
| EPP | `performance` |

Comprobar: `cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_governor` →
`performance`; `cat /sys/class/devfreq/13040000.gpu/cur_freq` → `900000000`.

## Terminal con teclas auxiliares (estilo Termux)

Squeekboard incluye los layouts `terminal/*`. En `kgx` se activa solo y muestra la fila
`Tab Ctrl Alt Shift ↑ ↓ ← →`, además de `>_` y globo de layouts. Captura verificada en
hardware: teclado del terminal con esas teclas.

## Navegador

`epiphany` 51.3 instalado y probado (pantalla de bienvenida de GNOME Web a pantalla
completa). Avisos inofensivos de `libenchant`/secret service; para guardar contraseñas
haría falta `gnome-keyring`.

## Audio: no hay tarjeta de sonido (bloqueo de kernel)

`/proc/asound` no existe y `aplay -l` → *no soundcards found*. El kernel 7.1.0 no trae
driver de máquina para MT6785: `sound/soc/mediatek/` solo tiene 6797, 8173, 8183, 8186,
8188, 8189, 8192, 8195 y 8365. El codec `snd-soc-mt6359` sí existe, pero sin nodo
`sound` en el DTS ni driver de máquina no hay card. Es trabajo de kernel (driver AFE
MT6785 + nodo DTS + UCM), no de userspace.

## Batería: sin gauge en 7.1 (bloqueo de kernel)

`/sys/class/power_supply` solo expone `mt6360-chg` y `tcpm` (TYPE=USB). No hay nodo
`battery`/`capacity`. El stack completo (`mt6359-gauge`, `mtk-battery`, `mt6397-core`
gauge, `mt6359-auxadc` en `IIO_CHAN_INFO_PROCESSED`, nodo `battery-manager` con los
perfiles de begonia) vive en la rama **`battery-downstream`** de
`mt6785-mainline/linux`, basada en **6.16**, y no está mergeada en 7.1. En septiembre
sí hubo batería porque se corría 6.16.4 con esa rama. Para tenerla en 7.1 hay que
rebasar la serie y reconstruir el kernel/boot image.

Único dato disponible: canal IIO `MT6359/AUXADC` `in_voltage12_raw` (`batt_v`), crudo.
